FLOREST PDV MÓVEL 0.3.0 — ATUALIZAÇÃO DO APK 0.2.0
Pacote mantido: br.com.florestsistemas.pdvmovel | versionCode: 3

SITUAÇÃO DESTA ENTREGA
A migração do PDV Móvel foi aplicada ao Supabase e verificada tecnicamente.
Os testes isolados passaram; nenhuma venda real foi executada automaticamente.
A versão completa no celular ainda exige seu teste manual de login, caixa e venda.
Não houve commit, push ou deploy desta revisão. Aguarde a publicação autorizada
antes de baixar do GitHub. Os rótulos novos do site ERP também aguardam publicação.
Não execute os testes SQL técnicos no projeto real: eles usam banco sintético.

1. PRESERVAR A CONFIGURAÇÃO QUE JÁ FUNCIONA
Não reinstale Java, Node, Git ou Android SDK se já gerou o APK 0.2.0 com sucesso.
Mantenha o JDK 17 e as variáveis JAVA_HOME/ANDROID_HOME atuais.
Preserve .env.local e o keystore original. Não crie uma chave de assinatura nova.
Nunca publique senhas ou keystores. Não envie senhas ao Codex.

O gerador usa as mesmas variáveis de ambiente já previstas:
FLOREST_KEYSTORE_PATH (keystore original, fora da pasta do app/Git)
FLOREST_KEYSTORE_PASSWORD
FLOREST_KEY_ALIAS
FLOREST_KEY_PASSWORD
FLOREST_EXISTING_APK (arquivo do APK 0.2.0 anteriormente instalado)

Guarde o APK 0.2.0 fora de android\, por exemplo em uma pasta de backup ou APK-GERADO.
O gerador se recusa a usar como referência um arquivo que a compilação nativa possa
sobrescrever. Isso não muda nem recria a assinatura; preserva o arquivo original.
Se o versionCode instalado já for >= 3, será necessário um número maior em app.json.
O gerador interrompe a compilação em vez de rebaixar a versão silenciosamente.

Mantenha em .env.local a URL/chave PUBLICÁVEIS do mesmo Supabase do ERP.
Não use service_role ou sb_secret. Manifesto de atualização continua opcional.

2. BAIXAR SÓ O APLICATIVO, APÓS A PUBLICAÇÃO SER AUTORIZADA E CONFIRMADA
Não faça git reset, git clean nem apague a pasta existente.
No PowerShell, execute este bloco. Ele baixa apenas a pasta móvel e mantém os
arquivos locais ignorados, incluindo .env.local, keystores e APKs.

$repo = 'C:\Users\Usuario\Desktop\apk\Florest-Sistemas'
$app = Join-Path $repo 'florest-pdv-movel'
git -C $repo fetch origin main
if ($LASTEXITCODE -ne 0) { throw 'Falha ao baixar a versão publicada.' }
$configText = git -C $repo show origin/main:florest-pdv-movel/app.json
if ($LASTEXITCODE -ne 0) { throw 'Não foi possível conferir a versão.' }
$config = ($configText -join "`n") | ConvertFrom-Json
if ($config.expo.version -ne '0.3.0') { throw 'A revisão 0.3.0 ainda não está publicada nesta main. Aguarde a confirmação.' }
$temp = Join-Path $env:TEMP ('FlorestPDV-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $temp | Out-Null
git -C $repo archive --format=zip --output="$temp\pdv.zip" origin/main florest-pdv-movel
if ($LASTEXITCODE -ne 0) { throw 'Falha ao preparar os arquivos.' }
Expand-Archive -LiteralPath "$temp\pdv.zip" -DestinationPath $temp
Get-ChildItem -LiteralPath "$temp\florest-pdv-movel" -Force | Copy-Item -Destination $app -Recurse -Force

3. ABRIR O CMD E GERAR O APK
Abra o Prompt de Comando (CMD) e execute:

cd /d "C:\Users\Usuario\Desktop\apk\Florest-Sistemas\florest-pdv-movel"
GERAR_APK_FLOREST_PDV_MOVEL.bat

Também é possível clicar duas vezes no .bat. A janela fica aberta no fim.
Não precisa Expo Go, Metro no celular, EAS ou publicação na Vercel.
O npm pode atualizar os módulos do projeto usando package-lock.json; isso não
reinstala Java/Node/Android SDK, nem apaga .env.local ou troca seu certificado.

4. CONFIRMAR O SUCESSO
O Gradle deve mostrar BUILD SUCCESSFUL. Aguarde também a mensagem final:
APK RELEASE verificado: ...\APK-GERADO\Florest-PDV-Movel.apk
Só essa mensagem confirma que assinatura, pacote, versão, bundle e câmera passaram
nas verificações do gerador. BUILD SUCCESSFUL sozinho não comprova essas verificações.
Se houver ERRO, não use um APK intermediário. O APK anterior de entrega é preservado.

Arquivo final esperado:
C:\Users\Usuario\Desktop\apk\Florest-Sistemas\florest-pdv-movel\APK-GERADO\Florest-PDV-Movel.apk

5. ATUALIZAR O CELULAR SEM DESINSTALAR
Transfira o APK final por USB ou canal confiável. Abra no Android e confirme Atualizar.
Se solicitado, autorize instalar apps para o gerenciador de arquivos utilizado.
Com mesmo pacote/certificado e versionCode maior, instale por cima da versão 0.2.0.
Não desinstale a versão anterior nem gere outro keystore para resolver um erro.
Em caso de certificado incompatível, recupere o keystore original.

6. CONFERIR A VERSÃO E TESTAR
A tela de login e o cabeçalho devem mostrar 0.3.0. Também confira em Configurações >
Aplicativos > Florest PDV Móvel > Informações do aplicativo, conforme seu Android.
Abra sem Metro/computador e com internet.

Login ERP: informe Usuário, e-mail da EMPRESA e senha.
Login por e-mail pessoal: deixe Usuário vazio e use seu e-mail/senha Auth atuais.
O app não solicita ID manual de empresa. Confira empresa e operador após o login.
Teste teclado/Próximo/Entrar, visibilidade dos campos, clientes, produtos e câmera.
Consumidor Padrão não cria cadastro. Nota a prazo exige cliente cadastrado.
Descontos/acréscimos são por unidade. Lançamentos na tela preparam valores; somente
a confirmação do servidor efetiva a venda e os pagamentos nas tabelas do ERP.
Itens/cliente alterados descartam a preparação anterior de pagamentos.

A aba Vendas aplica filtros no servidor. Operador sem acesso financeiro vê suas
próprias vendas móveis; perfil financeiro também consulta o PDV Principal.
A aba Caixa usa sessão exclusiva deste celular, sem abrir/fechar o caixa do computador.
Depois de cada operação, reconheça o recibo do servidor antes de iniciar outra.
Em timeout, use Consultar resultado. Reenvie somente pela ação de mesma tentativa.
Não apague os dados do app nem abandone uma tentativa sem consultar seu resultado.

ATENÇÃO FISCAL: a configuração existente não é alterada. Empresas com emissão fiscal
ativa ou não confirmada não podem vender no móvel nesta revisão, pois o fluxo fiscal
ainda precisa ser integrado. Não desative essa configuração para contornar a restrição.

7. TESTE MANUAL NO CELULAR (MIGRAÇÃO JÁ APLICADA)
Entre na empresa de teste, confira empresa e operador e abra o caixa deste celular.
Escolha Consumidor Padrão, pesquise CERVEJA BRAHMA 600ML se cadastrada, confira preço
atual, quantidade, total e pagamentos. A cobrança externa é informada pelo operador.
Confirme uma vez. Aguarde Venda #... confirmada pelo servidor, reconheça o resultado,
consulte em Vendas, confira os pagamentos e o relatório do caixa e feche o caixa.
Confira a baixa no estoque e os relatórios do ERP. Os ajustes do HTML do ERP também
precisam de publicação autorizada antes de mostrar os novos rótulos no site servido.
O Codex NÃO executa essa venda comercial automaticamente nem a apresenta como testada.

8. CONEXÃO E LIMITES DOS TESTES
Confira Wi-Fi/dados móveis e data/hora do Android. Sem confirmação, a venda é pendente,
não uma nova venda. A mesma chave é preservada em armazenamento seguro até reconhecer
a confirmação/rejeição do servidor. Não há venda offline nem envio automático.
O gerador deve mostrar BUILD SUCCESSFUL E APK RELEASE verificado antes de instalar.
Saída final permanece APK-GERADO\Florest-PDV-Movel.apk. Instale como atualização por cima
da versão anterior, sem desinstalar e sem trocar o keystore. Confira 0.3.0 no cabeçalho.
Leia VALIDACAO.md e backend/LEIA-ME.md para a aplicação confirmada e os limites dos testes.
