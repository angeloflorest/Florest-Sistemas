# Preferências do Angelo

## Fonte oficial das atualizações do ERP — 23/10/2026

Antes de qualquer alteração no ERP, buscar o `florest-erp/sistema/index.html` mais recente da branch `main` do GitHub `angeloflorest/Florest-Sistemas` e usar essa versão como base. Conferir o SHA atual antes de publicar; se o arquivo mudar durante o trabalho, buscar a nova versão e reaplicar somente as alterações pretendidas. Nunca substituir o HTML atual por uma cópia local antiga nem por um snapshot histórico inteiro.

Preservar atualizações posteriores ao recuperar uma correção antiga. Comparar o diff final, validar o fluxo afetado e, após publicar, conferir se o HTML servido por `erp.florestsistemas.com.br` corresponde à versão enviada. Não incluir alterações locais pendentes de outras funcionalidades sem necessidade ou autorização. Não afirmar publicação concluída apenas porque houve commit: verificar também a versão servida.

## VPS e projetos futuros — registrado em 23/10/2026

Ao discutir novos projetos com Angelo, lembrar da ideia de contratar uma VPS (servidor alugado na nuvem) e explicar se o projeto pode aproveitar essa infraestrutura. Não presumir que todo projeto precisa de VPS.

Contexto: quer desenvolver o Florest Support usando RustDesk, com identidade da Florest, transferência de arquivos e acesso permanente autorizado aos clientes. Faz um atendimento por vez, com frequência variável. Ainda não contratou VPS nem licença RustDesk Pro. Possui florestsistemas.com.br no Registro.br; ERP e portal de aplicativos apontam para Vercel, e a base atual está no Supabase gerenciado.

A VPS inicial considerada para suporte remoto não deve ser tratada como suficiente para hospedar todo o Supabase. Preferência discutida: manter o ERP e Supabase atuais e avaliar a VPS para suporte, automações, integrações, testes e monitoramento. Qualquer contratação ou migração exige decisão específica do usuário; esta nota não autoriza compras ou migrações.

## Aprovações das atualizações — 23/10/2026

As respostas de Angelo às perguntas deste chat autorizam publicar e aplicar os itens selecionados, incluindo Git e Supabase quando necessários à atualização. Não solicitar novamente a mesma autorização nem deixar um item aprovado apenas preparado sem explicar uma limitação concreta. Respeitar as escolhas de manter como está e o escopo de cada atualização.
